# ユースケース一覧

## 概要

要件定義（v1）から抽出したユースケースを整理する。

---

## 1. 日次バッチ系

### UC-1: 買いシグナル判定＆新規注文

- **アクター**: システム（日次ジョブ）
- **トリガー**: 毎日1回（市場クローズ後 or 固定時刻）
- **事前条件**:
  - `is_buy_enabled = true`
  - 累積確定損益 > -1000円
  - 空きポジション枠がある（現在保有数 < 10）
- **主フロー**:
  1. 監視銘柄リストを取得
  2. 各銘柄の日足データを取得
  3. 買い条件を判定
  4. 条件を満たす銘柄に対して新規買い注文を発注
  5. 注文結果をDBに記録
- **事後条件**: 新規注文がordersテーブルに記録される

### UC-2: OCO注文（TP/SL）発注

- **アクター**: システム（日次ジョブ）
- **トリガー**: UC-1の買い注文が約定した後
- **事前条件**: 買い注文が約定している
- **主フロー**:
  1. 約定した買い注文のエントリー価格を取得
  2. TP価格を計算（エントリー価格 × 1.10）
  3. SL価格を計算（エントリー価格 × 0.95）
  4. OCO注文（TP/SL）を証券会社に発注
  5. 注文情報をDBに記録
- **事後条件**: OCO注文がordersテーブルに記録される
- **備考**: 売り注文は証券側に置き、システム停止しても決済される

### UC-3: 日次レポート送信

- **アクター**: システム（日次ジョブ）
- **トリガー**: 日次ジョブの最後
- **主フロー**:
  1. 本日の確定損益を集計
  2. 累積確定損益を計算
  3. 現在の保有ポジション数を取得
  4. 本日の新規買い件数を取得
  5. Discordへレポートを送信
- **通知内容**:
  - 本日の確定損益
  - 累積確定損益（停止ライン: -1000円）
  - 保有ポジション数（x/10）
  - 本日の新規買い件数

---

## 2. ポーリング系

### UC-4: 約定検知＆DB反映

- **アクター**: システム（ポーリングジョブ）
- **トリガー**: 5分ごと
- **主フロー**:
  1. 未処理の注文（status=OPEN）をDBから取得
  2. Webull APIで各注文のステータスを確認
  3. 約定（FILLED/FINAL_FILLED）を検知した場合:
     - ordersテーブルを更新
     - positionsテーブルを更新（CLOSEDに）
     - tradesテーブルに損益を記録
  4. Discord通知を送信（UC-6）
- **事後条件**: 約定情報がDBに反映される

### UC-5: 損益集計＆停止判定

- **アクター**: システム（ポーリングジョブ / 日次ジョブ）
- **トリガー**: 約定検知時 / 日次集計時
- **主フロー**:
  1. tradesテーブルから累積確定損益を計算
  2. 累積確定損益 ≤ -1000円 の場合:
     - `is_buy_enabled = false` に更新
     - Discord通知（新規買い停止発動）
- **事後条件**: 停止条件を満たした場合、新規買いが停止される

---

## 3. 通知系

### UC-6: Discord通知（取引イベント）

- **アクター**: システム
- **トリガー**: 各種イベント発生時
- **通知種別**:
  | イベント | 通知タイミング |
  |---------|---------------|
  | 利確成立（TP） | 即時 |
  | 損切り成立（SL） | 即時 |
  | 新規買い停止発動 | 即時 |
  | 例外/エラー | 即時 |

### UC-7: キー期限アラート

- **アクター**: システム（日次 or 定期チェック）
- **トリガー**: キー期限チェック時
- **主フロー**:
  1. DBから`secret_expires_at`を取得
  2. 残り日数を計算
  3. 残り7日以下: 通常通知
  4. 残り2日以下: 強通知（＋新規買い停止も検討）
- **事後条件**: Discord通知が送信される

---

## 4. 管理系

### UC-8: キー更新（人間介入）

- **アクター**: 管理者（人間）
- **トリガー**: キー期限アラート受信後 / 手動
- **主フロー**:
  1. 管理画面で「キー更新開始」をクリック
  2. Webull管理画面でSMS認証を実施
  3. 新しいApp Secretを取得
  4. GCP Secret Managerに新バージョンとして保存
  5. DBの`secret_expires_at`と`last_rotated_at`を更新
- **備考**: Secretは再表示不可のため、発行時に必ず保存する

### UC-9: 手動での買い停止解除

- **アクター**: 管理者（人間）
- **トリガー**: 手動
- **事前条件**: `is_buy_enabled = false`
- **主フロー**:
  1. 管理画面にアクセス
  2. 現在の累積損益・状態を確認
  3. 「買い停止解除」を実行
  4. `is_buy_enabled = true` に更新
- **備考**: 追加入金後など、意図的に再開する場合に使用
